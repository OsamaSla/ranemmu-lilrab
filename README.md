# هلم نرنم — Halma Naranaam

An offline-first Arabic hymns app built with [Expo](https://expo.dev) (SDK 57),
TypeScript, `expo-router` and `zustand`. UI in Arabic (RTL) by default, with
English and German locales wired in.

## Get started

```bash
npm install
npx expo start        # dev server — open in Expo Go, emulator, or web
npx expo start --web  # fastest first look, no phone needed
```

Quality gates (run before committing):

```bash
npx tsc --noEmit
npx expo lint
npm run check:hymns
```

## Content workflow (no coding required to add hymns)

Hymns are typed in Word, never in JSON:

```
content/Template.docx  --typist-->  book batch .docx
        │                                     │
        │                          npm run import:word -- batch.docx
        │                                     ▼
        │                          content/book-batch.json
        │                                     │
        │                          npm run check:hymns   (validate)
        │                                     │
        │                          npm run build:corpus  (bundle)
        ▼                                     ▼
regenerate with                 assets/hymns/ + src/data/generated-chunks.ts
npm run make:template
```

- `content/Template.docx` is generated by `scripts/make-template.mjs`. It
  carries its own Arabic instructions, a worked example, and a copy-paste
  skeleton. Four styles drive the import: `Hymn | عنوان`, `Verse | بيت`,
  `Chorus | لازمة`, `Info | معلومات`. Anything in Normal style is a note to
  the editor and is never imported.
- `scripts/import-word.mjs` maps styles to hymn records in document order, so
  a refrain typed between any two stanzas renders exactly there. `(١)`-style
  prefixes become stanza labels, `Tab` joins side-by-side half-lines with `❖`,
  `key: value` Info lines fill tune/key/author/composer/metre/chorus-label.
- `scripts/check-hymns.mjs` validates every `content/*.json`: unique numbers,
  non-empty verses, no stray non-Arabic characters, no unfilled `…`
  template placeholders — plus a vocalisation-coverage report that spots OCR
  or extraction damage early.

Until the real book arrives, `content/seed.json` holds 10 Psalm-based
placeholders so every screen is exercisable. Delete it once real content lands.

## Project layout

- `src/app/` — routes: `(tabs)` (home, recents, help, more), `library`,
  `search`, `hymn/[id]` reader, `structure`, `favorites`, `settings`
- `src/data/` — hymn types, Arabic search normaliser, search engine, loader
- `src/i18n/` — `ar` source strings; `en`/`de` typed against it
- `src/theme/` — design tokens, 6 bundled OFL Arabic fonts
- `src/store/` — persisted settings (theme/locale/fonts/sizes) and library
  (favorites, recents)
- `src/components/` — shared UI (cards, rows, sheets, modals)
- `scripts/` — content tooling only; never bundled into the app
- `assets/fonts/` — generated by `npm run fonts` (static TTF instances)

## Release

Cloud builds, no local Android SDK needed:

```bash
npx eas-cli@latest build -p android --profile preview   # APK for testing
npx eas-cli@latest build -p android --profile production # AAB for Play Store
```
